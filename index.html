Workshop 12 — Windows Server lab

Step-by-step setup: static addressing, Active Directory, DHCP and DNS, FTP and SMTP, and a simple HTTP site. Follow in order; server restarts after domain promotion are expected.

Lab topology

Host-only VirtualBox network: Arch client via vboxnet0, Windows VM as DC and services on 192.168.13.0/24.

1. Configure a static IP

Domain controllers need a fixed address so clients and DNS always resolve the same host. Set IPv4 manually before installing roles.

Network adapter

Open adapter settings, choose the interface that faces your lab LAN, and assign IP, subnet mask, and DNS (you can point DNS at this machine after AD DNS is installed).

2. Active Directory Domain Services (AD DS)

Promote the server to a domain controller. Wizard collects forest and domain names, paths for AD database and SYSVOL, and recovery password.

Install role

Server Manager → Add Roles and Features → Role-based installation → select this server → check Active Directory Domain Services. Add required features when prompted.

Domain name and paths

After install, use Promote this server to a domain controller. Choose Add a new forest and enter your DNS root name (example in lab: wei.js.com.co). Set NetBIOS name, folder locations, and DSRM password. Review prerequisites; DNS delegation warnings are common in isolated labs.

Domain controller options

Select functional levels, confirm Domain Name System (DNS) server and Global Catalog as required for first DC in forest. Install from media (IFM) only if you use that workflow; otherwise continue with defaults appropriate to your lab.

Wizard pages

Use Next through additional options, paths, review, and prerequisite check. When the checklist passes, click Install. Promotion runs and the host reboots automatically.

Prerequisites and reboot

Prerequisite validation should show green checks for a simple lab. After promotion completes, sign in with domain credentials. Server Manager opens on a fresh session.

3. Additional roles: DHCP and Web Server (IIS)

Install DHCP for client addressing and IIS for HTTP and later FTP. Add features together in one pass to reduce reboots.

Role selection

Add Roles and Features → select DHCP Server and Web Server (IIS). Complete dependencies, then finish the wizard.

FTP role service

Advance with Next until Role Services for Web Server. Enable FTP Server (FTP service and FTP extensibility as needed for your lab). Complete installation.

4. DHCP scope and DNS records

Authorize DHCP in AD, create a scope for your subnet, set default gateway and DNS options, then add an A record in the forward lookup zone for hosts that should resolve by name.

Post-install DHCP

Server Manager shows DHCP post-install configuration. Complete it so the service is authorized in the domain and bound to your server.

New scope

Tools → DHCP → expand server → IPv4 → right-click IPv4 → New Scope. Wizard asks for name, IP range, exclusions, and lease duration.

Scope IP range

Define start and end IP consistent with your lab subnet. Exclusions optional for reserved addresses (servers, printers).

Activate scope

When asked whether to activate the scope now, choose Yes so clients can obtain leases immediately after you authorize the server if required.

Default gateway option

In scope options (or during wizard), set Router (003) to your lab default gateway so clients get correct outbound routing.

DNS servers option

Continue with Next where applicable. For DNS servers option (006), point clients to this DC or your chosen DNS so name resolution works with AD.

DNS host (A) record

Tools → DNS → Forward Lookup Zones → open your domain zone → right-click → New Host (A or AAAA). Enter hostname and IP for services you will test (HTTP, FTP, etc.).

5. FTP site in IIS

Publish a folder over FTP: physical path with content, new FTP site in IIS Manager, binding and SSL policy, then authentication and authorization rules matching your lab policy.

Content folder

Create a directory on disk (example: under C:\inetpub) and add a small test file so uploads and downloads are easy to verify.

Add FTP site

Tools → Internet Information Services (IIS) Manager → expand server → Sites → right-click → Add FTP Site. Name the site and set the physical path to your folder.

Binding and SSL

Choose IP, port (21), and whether to allow or require SSL. For isolated lab testing, No SSL is common; production would use FTPS and certificates.

Authentication and authorization

Enable basic or anonymous as your exercise requires. Authorization can allow specified users or groups read/write to the FTP root.

6. SMTP

Legacy SMTP in Windows uses IIS 6.0 Manager. Create a mailbox user in AD, install SMTP feature, tune authentication and relay so the server can accept or forward mail in the lab.

Domain user for mail

Tools → Active Directory Users and Computers → Users → right-click → New → User. Complete logon name and password options. This account can be used when clients authenticate to SMTP if configured.

User properties

Finish the wizard with password policy appropriate to your course. Optionally set email fields on the user object if your lab tracks them there.

Install SMTP Server feature

Add Roles and Features → Features → enable SMTP Server. Confirm management tools if offered. Restart if the installer requests it.

IIS 6.0 Manager — authentication

Tools → Internet Information Services (IIS) 6.0 Manager → expand server → SMTP virtual server → Properties → Access → Authentication. Configure anonymous or integrated authentication per lab requirements.

Relay restrictions

Still under Access / Relay: Relay → Add → specify IP range or single host allowed to relay through this server. Tight relay lists avoid open relay in real networks; lab may allow the server’s own subnet.

Test SMTP delivery

Run Send-MailMessage -From "jose@wei.js.com.co" -To "vero@wei.js.com.co" -Subject "Solicitud Registro" -Body "Mensaje de prueba enviado por SMTP" -SmtpServer "192.168.13.1" in PowerShell. Remember that the address must be configured in the SMTP server. The email file is placed in the Drop folder upon success, otherwise it would be located in another directory.

7. HTTP server (default site)

Replace default IIS web content with your own index.html, then confirm in a browser using the hostname or IP you published in DNS.

Remove default content

In the default web site’s physical path (often C:\inetpub\wwwroot), delete or move stock IIS welcome files so only your page is served.

Default document

Add index.html (or ensure Default Document feature lists index.html first). File should contain minimal HTML to prove the site is yours.

Browser test

From a client or the server, open a browser and navigate to the URL you configured earlier (FQDN from DNS or IP). You should see your page without certificate warnings for plain HTTP.

Linux Server Workshop — Rocky Linux 10.1

Step-by-step setup on Rocky Linux (Red Hat based): static addressing with NetworkManager, BIND DNS server, Kea DHCP server, vsftpd FTP server, Postfix and Dovecot email server, and a simple website with Apache httpd.

Lab topology

Isolated VirtualBox network (Host-only): Arch Linux client via vboxnet0, Rocky Linux VM server on the 192.168.13.0/24 subnet.

1. Static IP address and NetworkManager

Network servers require static addressing to ensure clients and DNS services always resolve to the same IP. Configure the network interface using nmcli before installing system daemons.

Rocky Linux 10.1 (Red Hat Base)

Initialization of the Rocky Linux 10.1 operating system, an enterprise distribution based on Red Hat Enterprise Linux (RHEL) source code, ensuring stability for network services.

Initial network state (DHCP)

By default, the enp0s3 interface receives a dynamic IP address (e.g. 10.0.2.15) assigned by the VirtualBox NAT service, which is not suitable for an infrastructure server.

Manual static IP assignment

Modify the connection using NetworkManager via the nmcli console tool. Set the method to manual, assign the static IP address 192.168.13.1/24, define the gateway as 192.168.13.254, and add the DNS servers. 

# Configure manual addressing
sudo nmcli con mod "enp0s3" ipv4.method manual \
  ipv4.addresses 192.168.13.1/24 \
  ipv4.gateway 192.168.13.254 \
  ipv4.dns "192.168.13.1,8.8.8.8"

# Apply changes to the adapter
sudo nmcli con up "enp0s3"

Adapter adjustment in the virtual machine

If a lack of connectivity or adapter not found error occurs, verify the virtual machine's network configuration in VirtualBox, ensuring the interface is in "Host-only" network mode linked to the correct adapter (e.g. vboxnet0).

2. Package installation and security policies

Install the network tools and servers for the lab. Then, open the ports in the system firewall and set SELinux to permissive mode to enable network interoperability.

System services and network utilities

Install the required services (BIND DNS, vsftpd FTP, Postfix SMTP, Apache HTTP) along with text editors and diagnostic commands using the dnf package manager. 

sudo dnf install -y bind bind-utils vsftpd postfix httpd telnet net-tools nano vim mailx

Modern DHCP server (Kea DHCP)

In modern RHEL-based distributions (like Rocky Linux 9 and 10), the classic ISC DHCP server has been replaced by Kea DHCP. Install the DHCP engine and its necessary dependencies. 

sudo dnf install -y kea kea-libs

Enable and start the DHCP4 daemon to ensure it loads at system boot. 

sudo systemctl enable --now kea-dhcp4

Firewall and SELinux policies

Permanently allow incoming traffic for all lab services (DNS, DHCP, FTP, SMTP, HTTP) in the firewall. Apply changes by reloading firewalld. Finally, change SELinux temporarily and permanently to permissive mode to avoid socket and shared folder blocks. 

# Permanently enable services in the firewall
sudo firewall-cmd --permanent --add-service=dns
sudo firewall-cmd --permanent --add-service=dhcp
sudo firewall-cmd --permanent --add-service=ftp
sudo firewall-cmd --permanent --add-service=smtp
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload

# Change SELinux to permissive (avoid service blocks in non-standard folders)
sudo setenforce 0
sudo sed -i 's/^SELINUX=enforcing/SELINUX=permissive/' /etc/selinux/config

Once the security parameters are configured, permanently enable and start the rest of the main services: 

sudo systemctl enable --now named vsftpd postfix httpd

3. Hostname and DNS server (BIND)

Define the fully qualified domain name (FQDN) of the server and configure BIND to act as the authoritative name server for the local domain, managing both forward and reverse resolution.

System Hostname definition

Set the hostname to wei.js.com.co using the hostnamectl system tool. 

sudo hostnamectl set-hostname wei.js.com.co

Confirm system changes by running hostname diagnostics.

General BIND configuration (named.conf)

Edit the main BIND directives file at /etc/named.conf. Change the listen-on port 53 lines to listen on any server network interface (or add 192.168.13.1) and modify allow-query to allow queries from any host or the local 192.168.13.0/24 segment. 

sudo nano /etc/named.conf

Forward Zone creation

Declare the forward zone for the wei.js.com.co domain inside the /var/named/ directory. Modify the file by adding the necessary resource records: the authoritative SOA record, the NS record pointing to the local server, and A records to map service URLs (servidor, www, ftp, mail) to the server's IP address. 

sudo nano /var/named/wei.js.com.co.zone
$TTL 86400
@   IN  SOA servidor.wei.js.com.co. admin.wei.js.com.co. (
        2024052401  ; Serial
        3600        ; Refresh
        1800        ; Retry
        604800      ; Expire
        86400 )     ; Minimum TTL

@        IN  NS  servidor.wei.js.com.co.
@        IN  A   192.168.13.1
servidor IN  A   192.168.13.1
www      IN  A   192.168.13.1
ftp      IN  A   192.168.13.1
mail     IN  A   192.168.13.1

Reverse Zone creation

Declare the reverse resolution zone to allow resolving names from IP addresses in the 192.168.13.0/24 subnet. Create the corresponding zone file using PTR records to map the last octet of the addressing to the previously defined hostnames. 

sudo nano /var/named/13.168.192.rev
$TTL 86400
@   IN  SOA servidor.wei.js.com.co. admin.wei.js.com.co. (
        2024052401  ; Serial
        3600        ; Refresh
        1800        ; Retry
        604800      ; Expire
        86400 )     ; Minimum TTL

@   IN  NS  servidor.wei.js.com.co.
1   IN  PTR servidor.wei.js.com.co.
1   IN  PTR www.wei.js.com.co.
1   IN  PTR ftp.wei.js.com.co.
1   IN  PTR mail.wei.js.com.co.

Structural validation and daemon restart

Verify that the zone syntax is correct using the BIND validation commands and restart the named service if the check is successful. 

# Validate zone files
sudo named-checkzone wei.js.com.co /var/named/wei.js.com.co.zone
sudo named-checkzone 13.168.192.in-addr.arpa /var/named/13.168.192.rev

# Restart and verify DNS service state
sudo systemctl restart named
sudo systemctl status named

4. DHCP Server (Kea)

Configure the Kea DHCP engine to dynamically assign IP addresses within the lab subnet, delivering local gateway and DNS routes to client hosts.

Kea service configuration (kea-dhcp4.conf)

Edit the configuration file at /etc/kea/kea-dhcp4.conf in JSON format. Assign the enp0s3 network interface to listen for DHCP requests, define the lease database in memory, set the lease cycle, and declare the 192.168.13.0/24 subnet along with the IP pool (192.168.13.100 - 192.168.13.254) and global options (gateway, DNS servers, and domain name). 

sudo nano /etc/kea/kea-dhcp4.conf
{
"Dhcp4": {
    "interfaces-config": {
        "interfaces": [ "enp0s3" ]
    },
    "lease-database": {
        "type": "memfile",
        "persist": true,
        "name": "/var/lib/kea/kea-leases4.csv"
    },
    "valid-lifetime": 4000,
    "renew-timer": 1000,
    "rebind-timer": 2000,
    "subnet4": [
        {
            "subnet": "192.168.13.0/24",
            "pools": [
                {
                    "pool": "192.168.13.100 - 192.168.13.254"
                }
            ],
            "option-data": [
                {
                    "name": "routers",
                    "data": "192.168.13.1"
                },
                {
                    "name": "domain-name-servers",
                    "data": "192.168.13.1"
                },
                {
                    "name": "domain-name",
                    "data": "wei.js.com.co"
                }
            ]
        }
    ]
}
}

Persistence directory and service startup

Ensure the directory where active DHCP leases will be saved exists and has the Kea service owners. Afterward, restart the service and verify it's running without failures. 

# Ensure lease database permissions
sudo mkdir -p /var/lib/kea
sudo chown kea:kea /var/lib/kea

# Start DHCP4 server
sudo systemctl restart kea-dhcp4
sudo systemctl status kea-dhcp4

5. FTP Server (vsftpd)

Configure the vsftpd service to enable secure file exchange via local server system users, restricting login to allowed accounts.

Local user restriction (vsftpd.conf)

Open the service configuration file at /etc/vsftpd/vsftpd.conf. At the end of the file, enable user list checking and define that vsftpd should deny login to any user not explicitly in the user_list file. 

sudo nano /etc/vsftpd/vsftpd.conf
# Add at the end of the file to restrict access
userlist_enable=YES
userlist_file=/etc/vsftpd/user_list
userlist_deny=NO

FTP user creation and access policies

Create a local user with an active home folder and enter their access password. Then, append their qualified username to the /etc/vsftpd/user_list access control file to grant them login permissions. 

# Create system user and enter password
sudo useradd -m ftpuser
sudo passwd ftpuser

# Enable user by adding them to the whitelist
echo "ftpuser" | sudo tee -a /etc/vsftpd/user_list

# Restart vsftpd to apply changes
sudo systemctl restart vsftpd

Connectivity check and file exchange

From the host machine (Arch Linux) using the KDE Dolphin file manager, connect to the ftp://ftpuser@192.168.13.1 path. Enter the declared credentials to view and move files within the server's personal folder without policy restrictions.

6. Mail Server (Postfix + Dovecot)

Configure a complete local email flow. Integrate the Postfix daemon for outbound transfer (SMTP) with Dovecot for inbound reading (IMAP), facilitating access from clients like Mozilla Thunderbird.

Dovecot installation

Install the Dovecot package to provide the IMAP mail reception gateway on the server. 

sudo dnf install -y dovecot

SMTP Server Configuration (Postfix)

Edit the main Postfix directives file at /etc/postfix/main.cf. Configure the parameters to assign the FQDN to the server, define the primary mail domain, authorize listening on all system interfaces, and enable storage in Maildir format within each user's home directory. 

sudo nano /etc/postfix/main.cf
# Edit or add the following parameters
myhostname = servidor.wei.js.com.co
mydomain = wei.js.com.co
myorigin = $mydomain
inet_interfaces = all
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain
home_mailbox = Maildir/

IMAP Server Configuration (Dovecot)

Edit the Dovecot configuration to match the received mail location with the Maildir setup declared in Postfix. Open /etc/dovecot/conf.d/10-mail.conf and set the path. 

sudo nano /etc/dovecot/conf.d/10-mail.conf
# Change the default mailbox path
mail_location = maildir:~/Maildir

Next, edit the authentication directives in /etc/dovecot/conf.d/10-auth.conf to allow plaintext logins (necessary in local lab networks without SSL) and enable standard login mechanisms. 

sudo nano /etc/dovecot/conf.d/10-auth.conf
# Allow basic authentication without SSL
disable_plaintext_auth = no
auth_mechanisms = plain login

Finally, modify /etc/dovecot/conf.d/10-master.conf to define network listening ports, ensuring the standard IMAP port 143. 

sudo nano /etc/dovecot/conf.d/10-master.conf
# In the service imap-login { ... } section
inet_listener imap {
  port = 143
}

Mailbox and email account creation

Create the local users for email (e.g. jose and vero), which will automatically generate their personal storage directories and allow login authentication. 

# Create users and enter passwords
sudo useradd -m vero
sudo passwd vero

sudo useradd -m jose
sudo passwd jose

Firewall enablement and startup

Open the ports for email protocols (imap, imaps) in the system firewall, reload the configuration, and start/restart the main Postfix and Dovecot daemons. 

# Enable incoming mail services in the firewall
sudo firewall-cmd --permanent --add-service=imap
sudo firewall-cmd --permanent --add-service=imaps
sudo firewall-cmd --reload

# Restart and enable start on boot
sudo systemctl restart postfix
sudo systemctl restart dovecot
sudo systemctl enable dovecot

# Verify execution states
sudo systemctl status postfix
sudo systemctl status dovecot

7. HTTP Server (Apache httpd)

Deploy a local HTML content portal visible from LAN hosts using the Apache HTTP Server (httpd).

Apache web service verification

Verify the state of the Apache daemon to confirm it is loaded in memory and responding on HTTP port 80. 

sudo systemctl status httpd

Content directories and custom Index

Create or edit the index.html web file inside the default web server root directory at /var/www/html/, which will contain your site's custom design.

Owner adjustments, permissions, and restart

For Apache to properly read the content, assign the file owner to the apache user and adjust read and execute permissions. Afterward, restart the httpd service to refresh file descriptors. 

# Change owners to apache
sudo chown -R apache:apache /var/www/html

# Grant global read and execute permissions
sudo chmod -R 755 /var/www/html

# Restart Apache web server
sudo systemctl restart httpd
